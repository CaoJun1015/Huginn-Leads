## 目标

由实际使用者确认：口语化求购能够进入线索，供货、否定和规格冲突不会被错误判成命中，地区不再参与判断，线索中能够看到发送者 QQ。完成本卡前不继续开发新模块、AI 语义判断或自动生成商品简称。

“战7000”仅作为本次测试实例；规则本身仍使用任务中配置的通用商品别名。

- [ ] 当前代码至少包含提交 `22b779d`。

- [ ] 确认测试来源已启用，NapCatQQ 显示已连接。

### 2. 验证规格与地区边界

- [ ] 发送 `来酷战7000 I7 14650HX X5060 16G 1T 什么价，发货上海`，应为“命中”。
- [ ] 在线索详情中确认没有地区提取结果，也没有地区比较项。
- [ ] 将 GPU 改为 `X5070` 再发送，预期为“冲突”，原因中应指出 GPU 不符合。
- [ ] 只发送 `战7000什么价`，预期为“待核对”，不能凭空补出 CPU、GPU、内存或存储。

### 3. 验证联系人信息

- [ ] 在线索列表或详情中确认发送者昵称和 QQ 号可见。
- [ ] 使用 QQ 号搜索原文消息，能够找到对应记录。
- [ ] 不要求保存 QQ 密码；验收截图不得包含 `.env`、Token 或密码。

### 4. 验证历史消息重跑

- [ ] 选择包含已知测试消息的最小时间范围，先查看重跑预览数量。
- [ ] 执行重跑，等待状态完成。
- [ ] 确认旧的测试消息改用新判断结果，且人工备注、联系状态没有被清空。
- [ ] 不要对大范围真实聊天记录反复重跑。

## 验收标准

- A1～A7 不漏收，方向全部为求购；缺少规格时保持“待核对”。
- B1～B2 不得判成求购或命中。
- C1～C2 不产生线索；D2 不得进入任务候选。
- 完整且一致的规格能够命中，明确不同的规格能够冲突。
- 地区不被提取、不参与匹配，也不导致待核对或冲突。
- 被收录线索包含可搜索的发送者 QQ。
- 重跑完成后没有重复原文、重复线索或丢失人工处理状态。

全部满足则结论为“通过”。任何一项失败时，记录原文、任务配置、实际结果和原因，不立即扩大规则词库；先把可稳定复现的失败案例单独转为修复任务。

## 本卡不包含

- 强别名与弱别名的独立配置。
- 自动从商品全称猜测简称。
- AI/大模型语义判断。
- 新消息平台、主动通知或新的外部数据源类型。
- Release 构建或打包。
