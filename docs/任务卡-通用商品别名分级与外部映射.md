# 任务卡：通用商品别名分级与外部映射

| 项目 | 内容 |
|---|---|
| 编号 | HL-DEV-003 |
| 类型 | 开发与优化 |
| 优先级 | P1 |
| 状态 | 待验收后执行 |
| 前置任务 | HL-QA-002 口语化线索匹配真实验收 |
| 预计范围 | 后端规则、任务编辑、外部数据源映射、自动测试、使用说明 |

## 背景

当前任务只有一组不分级的触发关键词。外部库存任务通常只导入完整系列名，例如 `来酷战7000`，因此 `找一台战7000` 会在商品筛选层漏掉；如果直接把大量简称都作为普通关键词，又会让没有交易意图的消息进入待核对。

本问题不是继续增加“谁有、找、来个”等词语，而是让商品全称和简称承担不同的筛选职责。

## 目标

- 保留现有触发关键词作为“强别名”：单独出现即可进入判断。
- 增加可选“弱别名”：只有同时识别出求购或供货意图时才进入判断。
- 手工任务可以显式配置两类别名；外部库存任务在导入时自动添加弱别名，不要求发布后逐条编辑任务。
- 外部数据源只读取用户配置的简称列或查询计算列，不根据品牌、品类或字符串位置自动猜简称。
- 旧任务不修改即可保持现有行为。

## 最小数据约定

任务条件沿用现有 JSON，不新建商品主数据表：

```json
{
  "aliases": ["来酷战7000"],
  "weak_aliases": ["战7000"]
}
```

- `aliases`：现有强别名字段，保持兼容。
- `weak_aliases`：新增可选字段，缺失时视为空列表。
- 两组别名都去除空值、重复值；相同值同时出现时只保留为强别名。
- 不增加置信度分数、同义词表或行业专用字段。

## 判断规则

| 消息情况 | 处理 |
|---|---|
| 命中强别名 | 进入现有方向与规格判断 |
| 只命中弱别名，同时有明确交易意图 | 进入现有方向与规格判断 |
| 只命中弱别名，但没有交易意图 | 未命中 |
| 命中别名，但出现“不要了、已买到、没货、不出”等否定 | 未命中 |
| 强、弱别名都命中 | 按强别名处理一次，不重复生成线索 |

方向、规格、价格、数量、QQ 保存和地区忽略规则继续复用现有实现。

## 开发步骤

### 1. 后端条件兼容

- [ ] 任务条件校验接受可选 `weak_aliases`。
- [ ] 现有任务只有 `aliases` 时结果不变。
- [ ] 候选判断先识别商品别名与交易意图，再决定弱别名是否可进入。
- [ ] 同一消息不会因同时命中强、弱别名生成重复结果。
- [ ] 更新处理器版本，使用户可通过重跑应用新逻辑。

### 2. 手工任务编辑

- [ ] 保留“触发关键词”输入框，并标注为强别名。
- [ ] 增加一个可选“简称/弱别名”输入框，使用逗号分隔。
- [ ] 界面说明弱别名必须与求购或供货表达同时出现。
- [ ] 编辑旧任务时不自动搬移或重写已有关键词。

### 3. 外部数据源映射

- [ ] 保留现有 `alias_fields`，其结果发布为强别名。
- [ ] 增加可选 `weak_alias_fields` 映射；用户只配置一次，之后每次预览和导入都自动为每条库存记录生成 `weak_aliases`。
- [ ] 弱别名可来自外部查询的原始列或查询计算列，允许一列中使用英文逗号、中文逗号或换行分隔多个值。
- [ ] 预览页面分别显示强别名和弱别名。
- [ ] 导入和再次导入时自动更新本地快照中的弱别名；发布任务时直接携带，不需要用户逐任务补充。
- [ ] 外部记录的弱别名发生变化时，预览显示“变更”，确认导入后同步到对应任务的新修订。
- [ ] 外部数据库仍为只读；不向 Diaohuo 或其他来源回写数据。
- [ ] Diaohuo 只能作为配置实例，不在规则中写死“来酷”“联想”或电脑型号处理。

### 4. 解释与文档

- [ ] 线索或原文详情能够说明是强别名还是弱别名触发。
- [ ] 更新外部数据源文档，给出通用别名列示例。
- [ ] 提醒用户：没有外部简称列时，可在自定义只读查询中提供计算列；Huginn 导入器本身不猜测品牌或简称。

## 自动测试

- [ ] 旧条件只有 `aliases` 时，原有测试结果全部不变。
- [ ] 强别名 `来酷战7000` 单独出现，结果为待核对。
- [ ] 弱别名 `战7000` 单独出现，结果为未命中。
- [ ] `找一台战7000`、`战7000什么价` 命中弱别名并进入待核对。
- [ ] `我有战7000` 被识别为供货；对库存待售任务结果为冲突。
- [ ] `战7000不要了` 不产生线索。
- [ ] 同时出现 `来酷战7000` 和 `战7000` 只产生一条结果。
- [ ] 外部来源预览、导入、再次导入和发布均自动保留强弱别名且保持幂等，全程不手工编辑已发布任务。
- [ ] 完整单元测试、100 条规则样本和前端构建通过。

## 人工验收

使用一个通用测试任务：

```text
强别名：来酷战7000
弱别名：战7000
任务方向：我有库存待售
```

| 测试文本 | 预期结果 |
|---|---|
| `来酷战7000` | 待核对 |
| `战7000` | 未命中 |
| `找一台战7000` | 求购、待核对、收录 |
| `战7000什么价` | 求购、待核对、收录 |
| `我有战7000` | 供货、冲突 |
| `战7000不要了` | 未命中、不收录 |
| `大战7000次` | 未命中 |

## 验收标准

- 旧任务行为不变，无需数据库人工修复。
- 简称能够覆盖口语线索，同时不会让孤立简称大量进入待核对。
- 手工任务与外部库存发布任务使用同一套判断逻辑。
- 外部来源配置完成后，新增和变更库存记录都能在导入时自动获得弱别名。
- 别名完全来自用户配置或外部数据，不包含行业硬编码和自动猜测。
- 不影响 QQ 号保存、人工处理状态、任务重跑和外部数据库只读边界。

## 不在本卡范围

- 拼音、错别字、编辑距离或模糊搜索。
- AI/大模型语义判断。
- 自动从商品名称删除品牌或提取系列。
- 多行业商品知识库和全局同义词维护。
- 多行商品段落切分；如真实验收证明有需求，另建任务卡。
- Release 构建或安装包更新。
