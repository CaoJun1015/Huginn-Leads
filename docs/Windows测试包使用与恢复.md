# Windows 测试包使用与恢复

此 ZIP 是本地测试包。完整解压到可写目录后双击 start.cmd；程序自带运行时，使用和恢复不需要另外安装 Python 或 Node.js。不要只复制 exe，应保留 _internal、配置示例和所有随包文件。

首次启动会生成本目录 .env，并在窗口显示初始化码。打开 http://127.0.0.1:18080 设置本地密码；如需接入 QQ，请自行配置 NapCatQQ 的反向 WebSocket 与本地 .env 中的令牌。不要分享 .env、初始化码、业务数据库或备份。

先用 Ctrl+C 停止程序，等待进程退出。不要在旧程序仍运行时覆盖安装文件；升级前保留整个原目录及一致性备份。在系统页面点击“创建备份”，并检查“清理与备份结果”的最近成功时间。后台循环运行不代表备份已成功。

## 离线恢复

在解压目录打开终端，执行任一命令（路径含中文或空格时加双引号）：

```text
restore.cmd "backups\huginn-leads-备份时间.db"
HuginnLeads.exe restore "D:\备份目录\待恢复.db"
```

程序与恢复命令使用同一个操作系统文件锁。当前目录工作台仍在运行时拒绝恢复；异常退出后操作系统释放锁，无需删除 .lock 文件。此机制要求启动程序也已升级到本测试包版本；旧版程序不使用该锁，升级前必须明确停止旧版进程。

恢复会校验 SQLite 完整性、Huginn Leads 表结构、外键和受支持的连续 schema 版本，拒绝损坏、无关数据库和未来版本。输入错误不会覆盖现库。恢复前先在 backups 中生成唯一的 before-restore-*.db 一致性副本；副本保留供人工核对，不受普通每日备份份数清理。

备份先复制到本目录临时文件并再次验证，确认旧库 WAL 已写回且无活动 SQLite 使用者后，原子替换数据库，避免旧 WAL/SHM 混入恢复库。替换前失败保留原库和已生成的恢复前副本。恢复命令不启动业务服务，也不自动执行数据库升级。

恢复成功后重新运行 start.cmd。程序会原子升级受支持的旧版结构。重新登录后检查任务、线索、人工状态/备注、来源、数据量和系统状态；重启后账号先显示离线，真实连接建立才恢复在线。历史断线消息不会自动补回。

恢复数据库不恢复 .env 中的连接配置。未知版本或半应用旧库请先保全原库与备份，再参考源码项目的数据库迁移恢复说明；不要手动补版本号。备份和外部导出副本不会随在线库数据删除自动清除。

## 验收范围

本包在开发机的独立中文/空格目录使用合成数据验证。移除 PATH 中 Python/Node 的测试不等同干净系统验收；无 Python/Node.js 的干净 Windows 环境及真实 QQ/NapCatQQ 连续运行仍需现场验收。此测试包未公开发布，也不覆盖现有实例。
