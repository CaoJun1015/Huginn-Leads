# 线索证据保留与删除

适用版本：数据库迁移 006；HL-REL-003、HL-REL-004、HL-REL-005。以下行为已在临时数据库与合成消息上验证，生产旧库升级、真实账号和现场运行仍待验收。

## 人工补录和机器重跑

- 人工补录使用稳定的 `origin=manual` 标记，维持“人工加入 / 待核对”，不会改成机器匹配成功。机器重跑只更新和替代机器条目。
- 同一机器商品条目更新时保留人工状态、备注、更正值和已读时间。条目消失或变为不命中时，旧机器条目被标记为已替代，人工字段仍保存在原记录中；新商品条目不会继承另一商品的人工判断。
- 同一任务、原文的重复人工补录复用原记录。暂停、完成、归档的任务不会因补录或重跑自动恢复运行；其机器作业取消。
- 升级识别旧 `manual-` 键和证据 JSON 中的 `manual: true`，恢复这些条目因旧重跑被隐藏的可见性。已实际删除的记录无法恢复。

## 原文到期与证据快照

自动结果与人工补录在同一写事务中保存平台、账号、来源稳定 ID、来源类型、群/联系人号、来源显示名、原始消息号、原始消息时间和接收时间。发布者和证据正文沿用既有保存字段。展示名称为保存时的快照；更名不会改写已有证据。

原文到期后，完整原文及其评估按原规则清理，线索保留其证据片段、来源时间快照和人工跟进内容，直到线索证据自身保留期到期。搜索同时检索仍存在的原文和保留的证据正文。它不能搜索从未保存到证据中的原文片段。

升级从仍存在的原文回填快照。原文已丢失、无法回填的历史字段保持空值，页面显示“来源未知”“消息时间未知”等，绝不使用线索创建时间伪装消息时间。已保存的发布者、证据正文、备注不受影响。

## 按范围删除

已登录且带 CSRF 的 API 调用流程：

1. `POST /api/data/delete-preview?source_id=…&before=…`：至少指定来源或截止时间一个条件。返回 `message_count`、`lead_count`、`evidence_count`、`affected_tasks` 和一次性确认令牌。每条线索保存一份证据，因此后两种数量中的线索数与证据数相同；包含已替代条目。
2. `POST /api/data/delete`：使用同一范围参数，JSON 请求体为 `{"confirmation_token":"预览返回值"}`。返回实际删除的原文数和线索数。

来源参数是 `sources.id`，包含账号及群/联系人身份，不是裸群号。截止时间是**接收时间严格早于 before**，等于截止时间的记录保留；必须提供含时区的 ISO 时间，等价时区会归一化。两个条件一起提供时取交集。

预览和执行使用同一筛选函数，覆盖仍有原文和原文过期后仅存证据的记录。范围删除影响该范围内所有任务的线索，预览会列出这些任务，以及原文对应的处理作业/评估任务；不删除任务本身。其他账号同号来源、其他来源类型和范围外记录保留。

确认令牌有效期为 10 分钟，绑定范围且只可用一次，服务重启失效；范围改变或过期返回 400。预览是当时的数量，执行时仍按确认的范围处理，期间新增且落在该范围内的记录也会计入实际删除数。失败操作整体回滚，返回 `409 delete_failed`，需重新预览；错误响应不包含业务正文。

缺失来源 ID 的旧证据不能按来源删除；缺失接收时间的旧证据不能按截止时间删除；联合范围要求两个字段都已知。这些记录可通过删除所属任务及其线索处理，不能猜测其归属扩大范围。

## 删除任务与归档

- `POST /api/tasks/{id}/delete-preview?delete_leads=false` 后，带同一标志和令牌调用 `DELETE /api/tasks/{id}`：沿用归档，保留线索并取消待处理、延后、处理中的作业。
- `delete_leads=true`：在单一事务内先删除该任务作业，再删除重跑记录，最后删除任务；任务修订、来源关联、评估与线索依既有外键级联删除，外部库存记录的 `task_id` 置空。外键检查始终开启。
- 单个任务删除保留共享原文、其他任务及其线索。处理中的旧作业在写入前重新检查作业和任务状态，不在删除后重新生成结果。
- 重用或过期令牌返回 400；已删除任务的预览返回 404；另一枚有效令牌在任务已被删除后执行同样返回 404。数据库删除失败返回 409，所有关系回滚。

## 升级和备份限制

006 使用第 1 轮修复后的迁移运行器；新增字段、人工来源回填、可见性恢复、来源快照和版本登记一起提交，失败一起回滚。空库、完整旧库升级、登记失败注入、重试和重复启动均有自动回归。

升级前仍应保留一致性备份；已有半应用历史库按[数据库迁移恢复](数据库迁移恢复.md)处理，不直接补版本号。数据库内删除不会清除历史备份、导出文件或外部副本；本机备份仍由既有备份保留策略管理，外部副本需另行管理。
